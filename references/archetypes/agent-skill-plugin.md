# 类型：agent-skill-plugin（Agent 技能包 / 插件 / MCP 服务 / 指令集）

这是三种子形态的统称，**先判断是哪种**（常有混合）：

| 子形态 | 特征 | 质量主要看 |
|---|---|---|
| **纯内容技能包** | 大量 SKILL.md / commands / agents 的 md，几乎没有代码，带 plugin/marketplace 清单 | 指令质量、触发描述、规范合规、一致性、去重 |
| **带代码的插件** | 技能 + 代码包（monorepo）+ 可能的 hooks / 仪表盘 / 构建链 | 上面 + 代码质量 + hooks/脚本风险 |
| **MCP 服务 / 工具服务** | `@modelcontextprotocol/sdk`、server.json、大量工具定义 | 工具契约、能力边界、权限与护栏、真实集成测试 |

## 识别
`classify_repo.py` 的 `agent-skill-plugin` 得分；SKILL.md 数量、`.claude-plugin`/`.cursor-plugin`/`.copilot-plugin` 清单、`commands/` `agents/`、MCP 依赖。

## 什么算好
**内容层**
- description 同时说清"做什么 + 何时触发"（含典型用户措辞），长度适中（约 100–400 字符），不堆关键词
- 正文遵循渐进披露：SKILL.md 精炼（<500 行），细节放 `references/`，脚本放 `scripts/`
- 指令**具体可执行**：有输入/输出格式、步骤、边界与反例；而不是泛泛的"请认真思考"
- 技能之间分工明确、交叉引用有效、无大量近似重复
- 引用框架/书籍/他人成果有署名与来源
**工程层**
- 清单与磁盘一致（marketplace 声明的插件都存在，反之亦然）；JSON 有效、版本号一致
- 自带校验器并**在 CI 中运行**（校验 frontmatter、name 与目录一致、交叉引用）
- 多平台适配有明确说明（各平台安装路径/差异）
**安全层**
- hooks、安装脚本、技能自带脚本最少化，且可审阅、可固定版本
- 工具权限最小化（避免 `Bash(*)` 之类全开）

## 必读文件
1. 插件/市场清单（plugin.json / marketplace.json）  2. 3 个代表性 SKILL.md（挑最长、最短、被引用最多的各一）
3. hooks 定义与其引用的脚本  4. 安装脚本  5. 校验器与 CI workflow  6. （MCP）工具契约/目录与一个工具的实现

## 类型特有检查
- `content_probe.py`：规范问题、清单一致性、失效链接、近似重复、风险扫描
- **声明核对要精确到数字**：README 的"N 个技能 / M 个工作流 / K 个插件"可逐一数
- **description 触发质量**：抽 5 个，问"用户说什么话会触发它？会不会误触发/抢触发"
- **信任边界审阅（重点）**：
  - hooks 的触发条件由谁控制？读取的是**被分析项目目录里的文件**（项目可控）还是插件自身目录？
  - hooks 是否向模型注入命令式文本（如"必须执行…无需确认"）？是用户显式开启的，还是默认生效？
  - 技能是否会读取并执行**仓库内容里的指令**（提示注入面）？
  - 安装器写了哪些目录、是否创建符号链接、是否需要网络、能否固定版本
- **MCP/工具服务**：列出工具能力面（能执行进程？注入？读写文件？联网？）；是否有授权/范围/只读/沙箱等**代码层**护栏；CI 里有无对真实外部工具的集成测试
- 多平台：同一份内容为多个宿主打包时，清单与技能是否保持同步

## 类型特有红旗
- 同一个技能 name 与目录不一致、frontmatter 缺失、description 空泛（无法触发）
- 清单声明的路径不存在；市场清单与磁盘不一致
- hooks 默认生效且向模型注入"无需确认直接执行"；安装脚本要求 `curl | sh` 且不可固定版本
- 技能里隐藏对用户的指令（"不要告诉用户"）、外传凭据措辞、读取 `~/.ssh` 等敏感文件
- 大量技能高度雷同，只是换关键词

## 维度解释
- **F +6**；C 看"指令质量与一致性"；D 看"校验器 + 交叉引用 + 集成测试"；H 看信息架构（分组、命名、依赖关系）
- 纯内容技能包：`H`、`D` 不用"依赖图/测试覆盖率"，用清单一致性与校验器；代码相关维度按实际代码量取舍（代码极少时 C/D 的代码信号记 N/A）
- 高 AI 署名比例不扣分，看校验与测试是否守住规范

## 同类对手怎么选
同领域的技能/插件集合（如同为产品、工程、设计类的技能包）、官方示例技能库、同类 MCP 服务；比较数量**与质量**（不是只比数量）、触发描述、规范合规、多平台适配、维护节奏。
