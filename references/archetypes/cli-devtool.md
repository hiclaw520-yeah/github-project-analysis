# 类型：cli-devtool（命令行 / 开发者工具 / 编辑器扩展）

## 识别
package.json 有 `bin`、pyproject 有 `[project.scripts]`、Cargo `[[bin]]`、`cmd/` 目录、命令行解析库依赖、提供安装脚本。

## 什么算好
- **首次价值时间短**：安装一条命令、`--help` 清晰、默认行为安全且有用
- 退出码、错误信息、`--json` 等机器可读输出、可脚本化
- 幂等与可回滚：写文件/改配置前有确认或 `--dry-run`
- 跨平台行为一致（路径、换行、权限），升级机制明确
- 遥测默认关闭或可显式关闭，并在文档中说明

## 必读文件
1. 命令入口（解析与分发）  2. 一个会写文件/改配置/调用外部程序的命令  3. 安装脚本/发布流程
4. README 的"安装与权限"段  5. 测试（是否覆盖命令的参数组合）

## 类型特有检查
- **安装方式**：是否引导 `curl | sh`/`irm | iex`；脚本是否可固定版本、是否校验校验和；先读后评，**不要执行**
- **权限与副作用**：会改哪些目录（家目录、shell 配置、全局 npm）；是否需要 sudo
- **更新机制**：自更新是否静默、从哪里拉取
- **外部程序调用**：是否把用户输入拼进 shell 命令（命令注入面）

## 类型特有红旗
- 管道执行远程脚本且不可固定版本；静默自更新；默认开启遥测
- 无 dry-run 却批量改写/删除用户文件
- 用 `shell=True`/`exec(\`...${input}\`)` 拼接用户输入

## 维度解释
F +3（安装与权限）、E +2（上手速度）。D 看命令组合测试与跨平台矩阵。

## 同类对手怎么选
解决同一任务的 CLI（含老牌工具）；比较安装成本、速度、输出可脚本化程度、维护节奏。
