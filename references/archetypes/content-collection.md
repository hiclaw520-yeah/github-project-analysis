# 类型：content-collection（文档 / 教程 / awesome 列表 / 课程 / 数据集 / 模板文本）

## 识别
Markdown/文档占比高（>65%）、代码极少；awesome/合集 README；chapters/lessons/book/tutorial 目录；数据文件为主。

## 什么算好
- **准确**：抽查的事实、命令、数字、引用能核对；过时内容有标注
- **有结构**：分类清晰、粒度一致、有统一模板；新增一条的成本低
- **有取舍**：不是无差别堆链接——有筛选标准、一句话点评、淘汰机制
- **可验证**：链接有效、示例代码可运行、数据有来源与版本
- **可持续**：更新节奏稳定、接受 PR、有贡献规范与勘误流程
- 署名与许可清楚（内容的许可证 ≠ 代码许可证；转载/摘编他人材料要注明）

## 必读文件
README + 目录结构；3 个随机抽取的条目/章节（不要只读开头）；贡献指南；许可证；更新历史。

## 类型特有检查
- `content_probe.py` 的链接体检（失效数/外链域名分布）；`local_probe.py` 的更新节奏
- **抽样核验**：随机挑 5 个条目，点开核对是否仍有效、描述是否准确
- **去重与分类**：近似条目比例；分类是否有"其他"黑洞
- **导流与商业动机**：外链是否大量指向作者自营站点/联盟链接/付费产品（标注，不直接判坏）
- 来源与版权：是否大段搬运他人内容

## 类型特有红旗
- 大量失效链接且长期不更新；条目只有链接没有说明
- 搬运未授权内容；无许可证
- 为导流堆砌（同一站点占外链绝大多数且条目质量低）

## 维度解释
C 看"具体性/准确性/一致性/去重"；D 看"校验与链接有效性"；H 看信息架构；A 重点看 issue/PR 的真实性与被引用情况。代码类信号（测试比、依赖图）记 N/A。

## 同类对手怎么选
同主题的其他合集/教程/文档；比较覆盖面、筛选标准、更新频率、结构、许可。

## 报告章节
省略"运行架构图/核心链路"；用"信息架构"与"抽样核验结果"代替。
