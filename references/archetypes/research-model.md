# 类型：research-model（论文实现 / 模型训练 / 评测基准 / Notebook）

## 识别
Notebook 多、ML 框架依赖（torch/jax/transformers…）、`train.py`/`eval.py`、README 含论文/引用/基准字样。

## 什么算好
- **可复现**：环境（锁定版本/容器）、随机种子、数据来源与版本、训练命令、评测命令齐全
- **与论文一致**：关键设置/超参可见，差异有说明
- **结果可对照**：给出基线与指标，并说明硬件与耗时
- 代码可读：配置与代码分离，实验可追踪
- 数据与模型的**许可与来源**清楚

## 必读文件
README 的复现步骤；训练入口；评测脚本；配置文件；`requirements`/环境文件；数据说明。

## 类型特有检查
- 复现路径是否完整可走通（至少静态走一遍：缺哪个文件/数据/权重？）
- 评测是否可能**数据泄漏**或"为跑分而写"的捷径
- 权重/数据是否托管在会失效的位置；是否需要付费/受限数据
- 依赖是否固定（ML 项目的版本漂移破坏性很强）

## 类型特有红旗
- 只给结果图不给复现命令；关键数据/权重不可获得
- 评测集与训练集重叠迹象；只汇报最佳种子
- 许可冲突（用受限数据训练却标 MIT）

## 维度解释
D = 可复现性；F +2（数据/模型许可）；G 看方法的可迁移性。测试比不适用或权重很低。

## 同类对手怎么选
同任务的开源实现与官方实现；比较复现难度、结果对齐程度、维护活跃度、推理成本。
