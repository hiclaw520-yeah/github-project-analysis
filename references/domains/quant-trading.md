# 领域补充：量化 / 交易 / 盯盘 / 选股 / 回测类项目

金融类项目的"代码能跑"和"结论可信"是两回事。除通用七维外，逐项过下面这些，并把发现并入评分（主要影响 C、D、F、G）。

## 1. 数据源可靠性（最容易被忽视）

- 数据从哪来？官方/付费接口，还是爬取免费接口（东财、新浪、雪球等）、`akshare`/`efinance`/`tushare` 这类封装？免费爬取意味着**接口随时改版、限频、字段漂移**。
- 有没有**多数据源兜底**（主源失败切备源）、超时与重试、缓存？
- 数据时点：行情延迟多少？盘中数据与收盘数据是否混用？
- 复权处理：前复权/后复权/不复权用在哪？指标计算用错复权会直接得出错误信号。**涉及绝对价格或市值的条件（股价区间、流通市值）必须用不复权价**；比例/形态类指标才适合复权序列。做得好的项目会在代码注释里明确区分。
- **前视偏差的快速自查**：滚动窗口是否 `shift(1)` 排除当日（如"前 N 日最高价"）；盘后数据与盘中信号是否混用。
- 异常数据：停牌、涨跌停、除权除息日、退市、ST 的处理。
- 关闭 TLS 校验（`verify=False`）在爬财经站点很常见：看有没有注释说明理由，以及是否限定在特定 vendor。有理由的取舍 ≠ 疏忽，但要在报告里如实记录。

## 2. 交易规则建模

对 A 股尤其要查（也适用港/美）：
- **T+1**：买入当日不可卖。模拟盘/回测是否真的阻止了当日卖出？
- **涨跌停**：涨停无法买入、跌停无法卖出，回测是否假设一定能成交？
- **涨跌停幅度要按板块区分**：主板 10%、创业板/科创板 20%、北交所 30%、ST 5%、新股上市初期不设限。代码里若用统一的魔法数字（如 `close >= prev_close * 1.095`）判定"涨停"，会对其他板块系统性误判——用 grep 找涨停/跌停判定，看有没有板块/ST 区分。
- **交易日历与时区**：是否内置节假日/半日市；港股/美股夏令时；周末不触发调度。
- **最小交易单位**（A 股 100 股一手）、**资金结算**（T+1/T+2）。
- **费用与滑点**：佣金、印花税、过户费、滑点是否建模。没有则收益被高估。
- 项目 README 若坦言"未建模 X"，是加分的诚实；若不提，去代码里验证。

## 3. 回测与信号的真实性

- **前视偏差（look-ahead）**：信号计算是否用到了当日收盘后才有的数据？财报按"公告日"还是"报告期"对齐？
- **幸存者偏差**：股票池是否只含当前存活标的。
- **过拟合**：参数是否在同一段数据上调优并汇报？有无样本外/滚动验证？
- **业绩展示**：只给最佳曲线、无回撤/胜率/样本数/成本说明 = 营销。
- **纸盘 vs 实盘**：模拟成交价如何确定（收盘价？下一根开盘？）；是否区分"信号"与"可成交"。

## 4. LLM / 多智能体决策类（如"AI 盯盘""多 Agent 投研"）

同时参考 `ai-agent-llm.md`，另加：
- LLM 输出的是**分析材料**还是**直接下单指令**？有没有人在回路确认？
- 提示词里是否包含**真实的结构化数据**（行情、财务、技术指标），还是让模型凭记忆"回忆"？后者会产生幻觉。
- 是否有**预测评估**：对历史建议做事后复盘/打分（有 `prediction_evaluation` 之类模块是好信号）。
- 结论是否可追溯（推理链、数据来源、版本）。
- 模型成本与耗时有无计量。

## 5. 风控与合规

- 止损/止盈、仓位上限、单日最大亏损等是否是**一等公民**，还是只有买入信号。
- **免责声明**：README/UI 是否明确"不构成投资建议"。**金融工具完全没有风险提示 = 红旗**（至少要提醒用户自行承担风险）。
- 实盘对接：券商 API 的密钥如何存储？是否有只读模式？是否可能误下单？
- 涉及账户/持仓数据时，数据是否只存本地，是否有外发（通知渠道、遥测、LLM 提供商）——持仓信息发给第三方 LLM 是隐私问题，应在报告里指出。

## 6. 对"我要拿来借鉴/改造"的用户的额外建议

- 区分可直接借鉴的**工程层**（调度、通知、迁移、可观测、交易日历）与需要自行验证的**策略层**（信号逻辑、评分、阈值）。
- 策略层的阈值和权重**不要当真理**：先在自己的数据上做样本外检验。
- 看项目如何把"交易规则"做成显式模块（日历、结算、T+1 锁仓），这类建模往往比信号本身更值得学。
