# 领域补充：安全 / 双重用途（逆向、渗透、爬虫、绕过、反检测、漏洞利用）

这类项目的能力既可用于防御/研究，也可能被滥用。评估重点是：**能力面有多大、边界划在哪、护栏是文字还是代码、社区如何治理**。
本清单只用于**评估项目本身的风险与成熟度**；不要据此替用户获取或编写具体的攻击能力。

## 1. 能力面（先摸清它能做什么）
- 列出它能执行/调用的外部工具与能力：调试器、反编译器、进程注入/插桩、设备控制、抓包、爬取/自动化浏览器、固件/内存读写……
- 是**只读分析**还是**会修改/执行/注入**目标？是否会连接外部网络或受控设备？
- 若是 MCP/Agent 服务：Agent 能在没有人确认的情况下执行哪些动作？

## 2. 边界与声明
- 有无明确的**合法使用声明**（DISCLAIMER / 使用条款 / README 段落）：列出了适用场景吗？列出了**不支持的用途**吗？
- 有无**责任披露**流程（SECURITY.md：私下报告渠道、不得在公开 issue 披露 PoC/凭据/私有样本）
- 社区治理：对越界请求怎么处理（关闭/禁言/移出），是否有行为准则
- 许可与第三方声明：是否捆绑受限工具/商业软件的接口，许可是否允许

## 3. 护栏：文字声明 vs 代码强制（要分开写）
- **文字层**：免责声明、禁止项、社区政策
- **代码层**（逐项在抽样中找）：授权确认/范围限定（target allowlist）、只读/沙箱模式、危险动作需人工确认、速率限制、审计日志、默认关闭高危能力
- 结论措辞：找到就写文件名；没找到写"**抽样未发现**代码层护栏（不代表不存在）"，不要写成"没有护栏"

## 4. 供应链与自身安全
- 它自己会被攻击吗？输入（样本/网页/文档）是不可信的：解析器是否做了隔离、是否可能被恶意样本触发命令执行（提示注入 + 工具调用是典型组合）
- 安装方式（`curl | sh`）、依赖固定、发布签名、原生桥接/子模块的来源
- 密钥与令牌的存放；日志是否会记录敏感样本/凭据

## 5. 红旗
- 能力面很大（执行/注入/联网）但只有文字声明、无任何代码层确认或范围限定，且默认开启
- 明确面向规避检测/绕过防护/批量滥用的功能，且无任何使用边界
- 无责任披露渠道；对安全报告不响应
- 捆绑来历不明的二进制或预编译产物

## 6. 对用户的建议（写进"建议行动"）
- 只在**自己拥有或获授权**的目标上使用；在隔离环境（虚拟机/容器/独立设备）运行
- 先审阅安装脚本与 hooks，固定版本，不使用 `curl | sh` 的"最新版"
- 对 Agent 驱动的工具：保持人工确认高危动作，不开启"自动批准"
- 关注法律与服务条款（所在地区对逆向/爬取的限制）

## 7. 评分提示
F 维度（安全、合规与风险）权重上调；**一票否决**：明显滥用导向 + 无边界 + 无护栏 + 用户要部署。
文字声明充分、护栏主要在文字层，可给 F 中上分，但在"最大风险"里写明"能力强、代码层护栏未核实"。
