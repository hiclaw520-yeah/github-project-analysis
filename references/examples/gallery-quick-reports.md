# 四种不同类型的快速报告（校准用，采集日期 2026-10-16）

> 用途：演示同一套流程在**不同类型**项目上如何取舍维度、信号与章节。**数字会变，写新报告必须重新采集；这些不是模板内容。**
> 都是"快速模式"：未做同类对比（I 维度记 N/A）、未试跑、未执行仓库代码；证据强度在各报告开头标明。

## 1. 纯内容技能包 —— pm-skills
**类型**：agent-skill-plugin（纯内容技能包，small，151 文件、代码仅 3 个 py）　**证据**：跑了 page/local/classify/content_probe；抽读 1 个 SKILL.md 与校验器；未执行任何脚本。

- **结论卡**：🟢 学习 3.8 / 🟡 使用 3.7。结构规整的"框架→技能→工作流"内容包，规范零违规；使用风险低（无 hooks、无技能内脚本、无安装器），但**输出质量没有评测集可验证**，且单人维护。
- **类型适配**：测试比、依赖图、架构图全部不适用 → 用 `content_probe` 的规范体检、清单一致性、链接有效性、近似重复；"架构"= 信息架构（9 个插件按产品生命周期分组 → 69 技能 → 42 个串联命令）。
- **声明核对（精确到数字）**：README"69 skills / 42 workflows / 9 plugins" → 实际 SKILL.md 69、commands 42、插件 9，**完全吻合**。
- **内容体检**：69 个技能零规范问题；清单与磁盘一致；128 个 md、相对链接 10 个**0 失效**；description 中位 248 字符、无近似重复；正文中位 78 行、仅 1 个技能带 `references/`；自带 `validate_plugins.py`（校验 frontmatter、name=目录名、命令引用的技能存在）**并在 CI 运行**。
- **风险**：风险扫描未命中；**商业动机**：168 处外链指向作者自营站点、另有书籍链接——利好持续更新，但属于导流，应标注。
- **抽读**：`pre-mortem` 技能有明确的角色/场景/步骤与分类框架（Tigers/Paper Tigers/Elephants），并署名引用框架来源；但"逐步思考"类指令偏通用，无示例与边界反例。
- **数据**：27.1k star / 2.9k fork（0.11）、228 天（日均 119）；80 次提交、**4 个邮箱、头号 96%（单人）**；AI 共同作者署名 25%（不扣分，因有校验器与 CI 守住规范）；近 30 天 13 次。
- **局限**：只抽读 1 个技能；输出质量未评测；星数增长未核验。

## 2. 带代码的多平台插件 —— Understand-Anything
**类型**：agent-skill-plugin（带 TypeScript monorepo）+ cli-devtool，medium（519 文件，34k 行源码）　**证据**：全部脚本 + 读 hooks.json、安装脚本头部、自动更新提示文件；未执行任何脚本。

- **结论卡**：🟢 学习 3.8（边缘）/ 🟡 使用 3.6。结构清晰、测试扎实、跨平台打包用心；使用前必须审阅 **hooks 与安装脚本**。
- **结构**：`understand-anything-plugin/packages/{core, dashboard}` + `skills`（9 个）+ `agents`（10 个 md）+ 三个宿主的插件清单（`.claude-plugin`/`.cursor-plugin`/`.copilot-plugin`）；`arch_probe` 35 节点 30 边，**硬环 0 对、延迟导入掩盖的环 0 对**（另有父子目录互引，已排除）。技术栈：tree-sitter 解析 + zod 校验 + React/vite/zustand/d3/xyflow 可视化 + pnpm/vitest。
- **信任边界（重点）**：`hooks.json` 含 `SessionStart` 与 `PostToolUse` 两个钩子。`SessionStart` 钩子在条件满足时向模型注入命令式文本（"必须读取并执行…，无需向用户确认"）。核实结论：**由用户 `--auto-update` 显式开启**、注入的指令文件在插件自身目录、触发逻辑具体——属于**有意的自动化设计，不是恶意**。但**触发条件读取的是当前项目目录里的 `config.json/meta.json`（项目可控）**，且指令是"无需确认"，这是值得在使用前理解的信任边界。另：README 有 9 处 `curl | bash` 安装引导，`install.sh` 的平台表列出 14 个宿主（另有 Claude/Cursor/Copilot 的插件清单）、通过符号链接写入各宿主的 skills 目录，可用环境变量覆盖仓库地址。
- **内容规范**：9 个技能中 5 个 description 缺触发线索、1 个 SKILL.md 926 行（超过 500 行建议）。
- **数据**：86.5k star / 7.3k fork（0.08）、215 天（日均 402）；858 次提交、81 个邮箱（头号 67%、活跃贡献者 26）；**AI 共同作者署名 43%** 但测试比 0.61、有 CI、有校验脚本，不扣分；近 90 天 117 次、近 30 天 12 次（增速放缓）；开放 119 issue / 205 PR（积压）；2 个 >1000 行文件。
- **亮点**：增量更新链路（`prepare-incremental` + 对应测试为最大变更热点）；多宿主统一打包；核心库与可视化分包。
- **局限**：未对其他平台的适配效果逐一验证；hooks 后续的 `.mjs` 脚本只读了入口。

## 3. 大型 MCP 服务（双重用途领域）—— rea
**类型**：agent-skill-plugin（MCP 服务）+ cli-devtool + app（含 Electron/浏览器等），huge（4028 文件，34 万行 TS）；领域：**安全/双重用途**（逆向）+ AI Agent　**证据**：全部脚本 + 读 DISCLAIMER、SECURITY、README 声明、CI 清单；补全了完整提交历史；未执行任何脚本。

- **结论卡**：🟢 学习 3.8 / 🟡 使用 3.6。工程化（测试比 1.20、真实外部工具集成测试）和分层都很强；能力面很大、**代码层护栏本次抽样未发现**，使用应在隔离环境并只用于自己拥有或获授权的目标。
- **热度异常（未核验）**：275.8k star / 185 天（日均 1491）、fork 69.5k（0.25）、watchers 948。**页面写"提交总数 3"，克隆实测 3392 次**——页面计数不可信，必须交叉验证。星数异常增长只标注"未核验"（需抽样 stargazers），不下结论。
- **维护画像（需解释的爆发）**：3392 次提交、234 个邮箱、活跃贡献者 68、头号 50%；**2573 次集中在 10 月**（7 月 697、8 月 21、9 月 100）、近 30 天占全史 78%；fix 类 51%、AI 署名 12%；36 次 release；开放 607 issue / 424 PR。原因不明（可能是批量/自动化开发），不能当作稳定节奏。
- **结构**：分层明确——`src/domain`（115 个模块依赖它）→ `application` → `contracts`，`composition`（62 条出边）是装配根，下接 ghidra/hopper/frida/adb/gdb/native 等 provider；168 节点 743 边，**硬环 7 对**（如 `contracts ↔ domain`、`application ↔ artifacts`）+ 1 对靠延迟/类型导入掩盖，46 对父子互引已排除；25 个 >1000 行文件（最大为 4893 行的 Java Ghidra 桥）。
- **验证**：测试行/源码行 1.20；CI 有**针对真实外部工具的集成 workflow**（`real-hopper-linux`、`real-go-binary`、`real-evm-interface` 等），并有 oxlint/knip/jscpd/husky/release-please——对该规模和领域是很强的可靠性证据。
- **双重用途（按 `domains/security-dual-use.md`）**：`DISCLAIMER.md` 明确列出合法用途与**不支持的用途**（绕过 DRM/反作弊/认证、游戏外挂、复制受保护代码等），并规定越界请求关闭处理；`SECURITY.md` 要求私下披露、不得在公开 issue 贴 PoC/凭据。**文字层充分；代码层护栏（授权/范围/只读/沙箱）抽样未发现，不代表不存在**。2 处 `eval(`（一处为 showcase 脚本）未逐一审阅。
- **局限**：只抽样了 provider 的少数文件；未验证任何工具的实际分析质量；star 异常增长未核验。

## 4. 小型个人脚本（量化选股）—— Sequoia-X　*（演示"一票否决"）*
**类型**：script-tool + app-service，tiny（30 文件、1.3k 行）；领域：量化交易　**证据**：全部脚本 + 读策略基类、涨停策略、数据引擎的复权段；按 `domains/quant-trading.md` 抽查规则。

- **结论卡**：🟡 学习 3.4 / 🔴 使用 2.8 → **一票否决：仓库根目录无 LICENSE，页面也取不到协议**（默认保留所有权利，不能合法使用或二次开发）。适合当小而清晰的选股脚本样例来读，不适合直接拿来跑或改造后分发，除非先取得作者授权。
- **类型适配**：tiny 规模 → 不因缺 CI/架构文档扣分（B−3、D−3），但 **LICENSE 与风险声明不降标**。
- **结构**：`BaseStrategy(ABC)` + 7 个策略（海龟、高窄旗形、涨停洗盘、RPS 突破…）+ `DataEngine`（baostock → SQLite，多进程增量，333 行）+ 飞书推送；插件式策略设计干净。
- **声明核对**：baostock 后复权 ✅（`adjustflag="1"`）；增量更新 ✅；向量化 ✅；飞书推送 ✅（含测试）。
- **领域专项（量化清单）**：✅ 取流通市值时**明确用不复权价**（`adjustflag="3"`）；✅ 海龟策略用 `shift(1).rolling(20)` 排除当日，**避免前视偏差**；❌ 涨停判定在抽查的策略中**硬编码 `close >= prev*1.095`**，未区分创业板/科创板 20%、ST 5%、北交所 30%；❌ 无回测与交易成本；❌ README 无风险声明。
- **数据**：8.0k star / 1.6k fork（0.20）、年龄 3009 天（日均 2.7，按年龄归一后正常）；202 次提交、9 个邮箱（头号 75%，含 dependabot）；**最近一次提交 159 天前**，爆发集中在 2021、2022-12、2026-03/04；测试 2 个文件（比值 0.21）、无 CI。
- **局限**：只抽查了 2 个策略；未跑数据引擎；未核实其他板块的涨停处理是否在别处补充。
