## 1. 应用 / 服务 —— PanWatch（完整深度报告）
🟢 学习 3.9 / 🟡 使用 3.6。自托管 A 股盯盘+纸盘服务（FastAPI+React）。**亮点**：用 AST 测试强制分层规则、交易规则（T+1/日历/结算）显式建模并各有测试。**风险**：单人项目（98% 提交同一邮箱）、无风险声明、CI 无 lint。
**结构**：单进程，10 个业务模块 + 9 个平台包（架构图只画最关键的 5+5）；4 对环 = 1 硬环 + 3 软环。**核心链路**：APScheduler → BaseAgent → FailoverAIClient → 通知去重 → agent_runs，交易日历做闸门；上游 TradingAgents 有 4.1k 行 monkeypatch 适配层，版本落后 3 个 tag。
**报告结构**：结论卡 → 架构图 → 核心链路 → 亮点(每条带代价) → 取舍 → 数据快照 → 同类对比(PanWatch + 3 个对手) → 九维评分 → 声明核对 → 红旗复核 → 阅读路线 → 局限。

## 2. 纯内容技能包 —— pm-skills
🟢 学习 3.8 / 🟡 使用 3.7。测试比、依赖图、架构图**全部不适用**，改用规范体检：69 个技能零规范问题、清单与磁盘一致、README"69/42/9"数字与实际**完全吻合**、校验器在 CI 运行。**风险**低（无 hooks/脚本），但输出质量无评测；单人维护；168 处外链导流到作者自营站点（标注为商业动机）。

## 3. 带代码的多平台插件 —— Understand-Anything
🟢 学习 3.8（边缘）/ 🟡 使用 3.6。TS monorepo + 三个宿主的插件清单，0 对环，测试比 0.61，AI 署名 43% 不扣分。**重点在信任边界**：`SessionStart` 钩子向模型注入"无需确认直接执行"，用户 `--auto-update` 显式开启，属有意设计，但触发条件读取项目目录里的文件（项目可控），使用前应理解。
