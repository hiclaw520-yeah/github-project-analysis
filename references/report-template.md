# 报告输出模板

语言跟随用户（用户用中文就用中文）。结论先行，每个判断挂证据（路径 / 数字 / 采集日期）。用户要更短时压缩，但保留**结论卡、结构图、评分表**。

```
# 项目体检：<owner/repo>（<采集日期>）
**一句话定位**　**类型**：<主类型 + 并列类型 + 规模>　**目的假设**　**证据强度**：<读了什么 / 没读什么 / 是否执行过>

## 结论卡
推荐度：🟢/🟡/🔴（学习）　🟢/🟡/🔴（使用）· 核心是什么 · 最大亮点 · 最大风险 · 适合谁/不适合谁

## 结构   ← 代码类：架构图(≤12 节点)+枢纽/环/边界；内容类：信息架构图
## 核心链路 / 典型使用   ← 逐跳；核心抽象；护城河类型；上游依赖
## 信任边界与权限面   ← 插件/MCP/CLI/安装器必有；其他类型可省
## 亮点（证据 — 解决什么 — 可迁移 — 代价）　## 取舍与缺陷（结构性/局部性/风险性）
## 数据快照   ← 5–8 个关键数字，注明来源与日期
## 同类对比   ← 矩阵 + 定位 + 差异化 + 场景→选谁 + 迁移/组合建议
## 领域专项   ← 命中领域清单时
## 九维评分   ← 表 + 加权总评（学习 / 使用，注明权重与类型调整、N/A）
## 声明核对　## 红旗复核
## 值得学的 3 点（到文件）　## 应避开的坑　## 建议阅读路线（顺序+用时）
## 建议行动   ← 用/借鉴/跳过；上线前必做 3 件事；结论在什么条件下会改变
## 局限   ← 未读/未采集/未核验/未执行/浅克隆偏差
```
